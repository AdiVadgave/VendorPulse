# Dependencies & Access Requirements

> **Version:** 2.0 | **Date:** 2026-06-03
> **Audience:** Shell IT Service Management, Shell Identity, Shell Procurement, Zensar Delivery Manager
> **Purpose:** Single checklist of everything the delivery team needs in order to build, deploy, and operate VendorPulse for Shell

---

## How to read this document

Every row is something that **must exist** before the dependent piece of work can start. Items are grouped by domain (Identity, Azure, LLM, Messaging, Tooling, People). Each item has:

- **Owner** — who provides / approves it (usually Shell)
- **Lead time** — how long it typically takes to obtain
- **Blocks** — what cannot start until this is in place
- **Cost note** — explicit licence / subscription cost where applicable

We have deliberately erred on the side of "request it earlier than you think you need it". Several items below have **multi-week lead times** that, if missed, push the entire timeline.

## 4. LLM Provider — Choose Anthropic OR Azure OpenAI

### 4.1 Option A — Anthropic API (recommended)

| # | Item | Owner | Lead time | Cost note |
|---|------|-------|-----------|-----------|
| L1a | **Anthropic enterprise account** in Shell's name (or routed through Zensar's account with explicit Shell-tenancy contract) | Shell Procurement + Anthropic | 4–8 weeks | Variable; enterprise pricing typically $50–$200 per million input tokens, varies by model |
| L2a | **Anthropic enterprise DPA** specifying zero-data-retention, no-training, EU data residency | Shell Legal | 4–6 weeks (parallel with L1a) | Included in enterprise contract |
| L3a | **API key** issued, stored in Key Vault | Anthropic + Shell IT | 1 day after L1a | n/a |
| L4a | **Monthly LLM budget** agreed (we recommend ~$1,000/month for the workload, padded for surprises) | Shell finance | with L1a | $12,000/year nominal |

### 4.2 Option B — Azure OpenAI (alternative)

| # | Item | Owner | Lead time | Cost note |
|---|------|-------|-----------|-----------|
| L1b | **Azure OpenAI service quota approval** in Shell's Azure subscription (Microsoft application form, region-specific) | Shell + Microsoft | 2–4 weeks | n/a |
| L2b | **Model deployment(s)** for `gpt-4-turbo` or `gpt-4o` (whichever is current and tool-calling-capable) in West Europe | Shell Cloud + Microsoft | 1–2 weeks after L1b | Pay-per-token; rough parity with Anthropic |
| L3b | **Existing Microsoft enterprise terms** cover data handling — verify scope of "no training" clause with Microsoft account team | Shell Legal | 1 week | Included in EA |
| L4b | **API key + endpoint URL** stored in Key Vault | Shell Cloud + Microsoft | 1 day after L2b | n/a |

**Decision required from Shell during pre-mobilisation (before Day 1).** Our recommendation is **Option A — Anthropic** because:

1. The POC has been built and tuned against Claude's tool-calling semantics; switching costs are non-zero
2. Anthropic's tool-calling reliability for the agent pattern is, in our experience, currently best in class
3. Enterprise terms are negotiable and equivalent to Azure OpenAI on the data-protection axis

Option B remains viable; switching either direction is a configuration change, not a code change (see [§05 LLD §8](05_LLD_Backend_Shell.md#8-llm-service--provider-abstraction)).

## 9. Checklist summary — what blocks Day 1 of delivery

The following **must be in place on the Monday morning of Week 1**. The 3-week plan has no Phase 0 buffer; pre-mobilisation must complete these before kick-off:

- [ ] App registration created (I1, I2)
- [ ] OIDC redirect URIs configured (I8)
- [ ] Entra ID groups created (I5)
- [ ] Service mailbox provisioned and Application Access Policy applied (M1, I6)
- [ ] Azure subscription + resource groups available (A1, A2)
- [ ] Key Vault provisioned (A5)
- [ ] Postgres provisioned (A4)
- [ ] App Service plan provisioned (A3)
- [ ] LLM provider chosen and procurement initiated (L1 series)
- [ ] CI/CD platform + repo created (T1, T2)
- [ ] Product Owner (P2) and IT Architecture liaison (P3) named and briefed

Items that **can be in progress without blocking Day 1 (but must complete by the dates indicated):**

- Conditional Access exemption (I7) — non-prod can sometimes bypass; prod cannot — needed by Day 13 (prod environment provisioning)
- Vendor master import (P12 / data) — needed by Day 14 (pilot cycle kick-off)
- Production DNS hostname + TLS cert (A8, A9) — needed by Day 14 (production cutover)
- Final brand sign-off on email templates (P13) — needed by Day 8 (Outlook email template build)

## 10. Open questions for Shell to answer

1. Does Shell IT Security accept certificate-based credentials for app-only auth (vs. client secret)? *Assumed yes.*
2. Does Shell IT Operations have an on-call rota for the workload after handover, or is it follow-the-sun support from Zensar in year 1?
3. Will Shell-side users connect to the app only from corporate devices, or also from BYOD? *Affects Conditional Access policy choice.*
4. Are there specific tagging or naming conventions for Azure resources we should adopt? *We will follow Shell's IT Service Catalogue standard if provided.*
5. Does Shell maintain a list of pre-approved 3rd-party LLM providers? *If Anthropic is not pre-approved, that adds procurement time.*
6. Is there a Shell-internal Wiki / Confluence space where this documentation and operational runbooks should live alongside the codebase docs?
